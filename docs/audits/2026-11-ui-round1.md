# herdr-app UI 对齐审计 · 第 1 轮（2026-11）

目标不是「看起来像」，而是**逐屏可对照地一样**：同一份 core 状态，同一组动作，
官方 `herdr-app` 与 Kraal 的窗口里出现的元素、层级、尺寸、颜色、文案和入口一致。
本轮只记录差异，不修；第 2 轮修完后用同样的屏幕再拍一遍，直到一轮没有新条目。

## 环境与口径

| 项 | 值 |
|---|---|
| VM | Tart `kraal-agent`，macOS 26.6.2 (25G83)，Aqua |
| 官方 app | `/tmp/ui-audit/Herdr.app`，`herdr-app 0.1.12` |
| Kraal | `main` @ `ead61ed`，`Scripts/build-app.sh` 产物 |
| core | 隔离 `hc 0.1.17`，`HC_SESSION=ui-audit`，`XDG_STATE_HOME=/tmp/ui-audit/state` |
| 截图 | `kraal-gui shot` 按窗口截取；官方窗口 1280×820，Kraal 默认 1180×760 |
| 操作 | `herdr-app do …` / `kraal do …` 与 `kraal-gui click/key`，不碰宿主真实桌面 |

截图全部在 `docs/audits/2026-11/`。官方截图命名 `official-*`，Kraal 命名 `kraal-*`。

> **注意**：官方 app 是 mods 驱动的界面，Kraal 明确不做 JS mods（D7）。因此
> “Files / Changes / mod 面板”这类**由 mod 提供的入口**不在本轮要求里；但由
> app 本体提供的标题栏、tab、侧栏、状态栏、设置、命令面板必须对齐。两者混在
> 同一屏时，下面会标出「mod 入口」而不是笼统算差异。

## 一页结论

官方和 Kraal 现在**不是同一个视觉体系**：

- 官方是「macOS 原生窗口 + 顶部 titlebar 内嵌 tab + 268pt 侧栏 + 底部状态栏 +
  大量留白」；Kraal 是「自绘工具栏 + 第二行 space/tab 选择器 + 358pt 灰色侧栏 +
  无状态栏 + 终端贴边」。
- 官方的弹层（命令面板、设置、帮助、添加机器）是**居中、固定宽高、带分组和
  键盘提示**的对话框；Kraal 对应物是大小/层级/内容都不同的 SwiftUI sheet。
- 官方有完整的空状态欢迎流程和主题选择；Kraal 空状态只有一句 “No live terminal”。
- 终端字节、agent 数据、标题等内容层已经一致；差的是**呈现层**。

| # | 官方 | Kraal | 影响 |

### G. 已经一致、不要回退的部分

以下是第 1 轮确认没有差异或属于有意差异，后续不要“顺手改坏”：

- 终端内容来自同一份 core 的 PTY 字节；同一 `zsh` prompt 在两窗口都正确。
- agent 状态来自 OSC 7501；两侧都显示同一个 agent、同一个 `Needs you` 语义和 turn/时间。
- pane/tab/space 的标题（`zsh`、`~`、`Claude Code`）来自 core/document，不是本地编造。
- Kraal 不做 JS mods，因此官方 `Files`/`Changes` 等 mod 入口不要求出现；
  但**app 本体**的入口必须补。
- 品牌名、logo、app 图标可以保留 Kraal（不是 herdr-app 的复制品）。

## 第 2 轮验收方式

修完后必须在 VM 里重拍同一组屏幕：

1. 空状态 / 首次启动；
2. 一个 space、一个 tab、一个 pane；
3. 两个 tab；
4. 左右 split + 焦点切换；
5. 命令面板（query 为空 / 输入 `split`）；
6. 设置（Look / Keyboard / Machines）；
7. 帮助（`⌘/`）；
8. 一个 blocked agent（OSC 7501）；
9. 添加机器 dialog；
10. light + dark。

判据：同一状态、同一窗口尺寸下，逐个元素对照；差异条目为 0 才结束。
不允许用“看起来差不多”代替清单。
